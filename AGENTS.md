- booking_adjustments history is immutable (DB trigger guard_booking_adjustment_history): only status/void fields change, no deletes — fix a wrong adjustment by voiding and re-applying, so the audit trail stays true.
- Modify Stay defaults to "preserve" pricing: stored total + night-level clean delta (computeChangeDelta); full re-price only for unpaid inquiry/soft_hold/pending_* bookings, enforced server-side — so settled nights are never re-priced.
- Light theme is the default; bump the ThemeProvider storage key when the default changes so everyone resets once, then keeps their own toggle choice.
- Guest portal excludes the social Camp Pass/exporter; retain operational stay documents and the existing logbook so logistics remain the priority.
- Message edits are guarded by DB trigger guard_message_update: guests may change only read_at, and only admins may release drafts or set approved_by — so the thread stays an honest audit trail.
- Urgent guest incidents live in guest_escalations (kind='urgent_request'; NULL kind = legacy messaging handoffs) and change only through create_urgent_request / urgent_request_action, guarded by guard_escalation_lifecycle; guest_escalation_events is add-only — so incident status is server-enforced and auditable.
- After-hours escalation runs only in DB function run_urgent_escalations (pg_cron every 2 min, exits immediately when auto_escalation_enabled is off or nothing is open); roster/responders are management-approved rows (validate_duty_roster) — never auto-assigned.
- Guest phone/WhatsApp links are built only via src/lib/contactLinks.ts and saved E.164 through set_assistance_setting — one formatter so Settings, guest card and Front Desk never disagree.
- Audit tables (ops_config_audit, policy_settings_history, guest_escalation_events) are append-only via DB triggers; push log status "accepted" means push-service accepted, never device-delivered — so readiness never overclaims.
- Booking detail sheets use the shared scrollBody layout with safe-area-aware dismissal outside the scroll region — so installed iPhone users can always close a long booking.
- Existing account profiles are never overwritten by booking creation; booking names live in manual_guest_name and win in booking displays, while directory identity stays account-based, so friends sharing an email retain separate staying names.
- Staff name editing uses staff_edit_guest_identity with server-derived admin/manager authority, property checks and ID-only audit metadata; the shared GuestNameEditor keeps account and booking edits explicit.

- Privileged edge functions verify callers via supabase/functions/_shared/internalAuth.ts (service role, cron x-internal-token from integration_secrets, or server-derived staff role) — the public anon key is never proof of identity.
